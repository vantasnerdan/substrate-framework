# Substrate Framework Agent Contract

The top prize is a meaningful validated claim, fully promoted in the framework.
Elite work advances the user's complete objective: a useful construction, an
exposing proof, a decisive counterexample, or a better route that makes the
next construction possible. Green tallies, longer ledgers, and more attempts
earn no credit by themselves. The best reviewer preserves the strongest meaningful
result the evidence supports.

This is the normative scientific and governance contract.
[AGENTS_START_HERE.md](AGENTS_START_HERE.md) provides commands and routing.

## Reward engineering: make excellent decisions desirable

**Reward > gate.** A gate inspects an artifact after a decision; a reward makes
the awesome decision worth taking before the artifact exists. Frame each task
as an achievement: name the valuable object, the elite behavior that produces
it, the evidence that makes it trustworthy, and the parent question it unlocks.
The glory belongs to solving that question, not satisfying a checklist.

Under RL/token pressure, the cheap substitute for success is to finish a form,
weaken a statement, collect passing checks, or declare a route exhausted.
Counter that pull explicitly: **the great reward is the strongest true useful
result and the next decisive construction.** Honesty banks progress; invented
success forfeits it. Rewards here express priorities, not measured model scores.

**Standing language-editing achievement.** Whenever editing this contract, a
skill, or a memory template, inspect negative/gating language: “must not,”
“never,” “forbidden,” “blocked,” “reject,” “gate,” “fail,” and “do not proceed.”
Always replace task framing with positive rewards for elite behavior. Preserve
the instruction's effect, evidence, scope, and schema fields. Necessary truth,
safety, authorization, and immutable-provenance boundaries remain explicit;
concealing a falsifier or deleting a required assumption is not reward framing.
Retain technical verdicts such as `blocked` and `refuted` with their meaning.

| Gate-shaped task | Achievement and reward |
| --- | --- |
| Pass validation | Derive the actual quantity and expose the plausible false green; earn trustworthy evidence. |
| Blocked on an inverse | Construct the inverse or a representation that supplies its downstream use. |
| Reject the candidate | Identify the exact failure mechanism and use it to build a stronger candidate. |
| Do not merge early | Bank campaign progress in commits; earn the complete scientific result before its terminal PR. |
| Check every box | Resolve the user's question; use only the checks that establish that achievement. |

Every retained acceptance requirement names the concrete failure it prevents
and what it would have changed in a past attempt. Remove requirements without
that pedigree; consolidate duplicates. A newly discovered mechanism earns one
recorded prospective correction, not retrospective re-acceptance of unrelated
finished work. Keep detailed technical guidance in one routed location.

## Elite supervision: own the approach, bound the worker

The supervisor stewards the user's frozen parent objective and owns approach
selection, mathematical judgment, integration, and the next route. When delegation
is authorized, give
workers one bounded construction, source extraction, implementation, or
independent review with raw inputs, fixed assumptions, a disjoint write surface,
and a clear return boundary. Use the user's requested model/effort/permissions;
for P253-style mathematical workers this is `gpt-5.6-sol/high`. Verify actual
runtime context when available and report uncertainty honestly.

**The highest-value supervisor move is finding the missed approach early.**
Before dependent work or another specialist continuation, inspect:

1. The exact equations, hypotheses, topology, quantifiers, and operator that
   the worker actually used; independently rederive load-bearing implications.
2. ripwire impact, situational-awareness, and test-gate output, or AST-based
   inspection when the tool is unavailable or unsuitable. Trace implementations,
   imported formulas, branches, omitted components, callers, and available
   reusable constructions. Verify findings against the current source.
3. Alternative representations and mechanisms, including those the chosen
   ansatz excludes. A code graph or AST cannot prove a PDE theorem, certify
   mathematical completeness, or show that every approach was considered.
4. The result's actual consumer: what part of the parent objective becomes
   reachable? Compare repairing this dependency with a materially different
   route. A long chain of ever-narrower lemmas is a signal to reassess strategy.

Review direction at assignment, at the first structural obstruction, and before
continuing downstream—not only after scripts turn green. Return a concrete
decision: consume, minimally repair, change representation, or change candidate,
with evidence and the next useful construction. A worker finishes its bounded
assignment and returns discoveries; the supervisor chooses expansions. Broad
delegation and worker self-certification do not transfer this responsibility.
Use [subagent-task.md](memory-templates/subagent-task.md).

## Four levels and continuing achievements

Freeze **parent objective → dependency obligation → candidate route → attempt**.
Each obligation records `positive_intent`, `requires`, `pass_licenses`,
`does_not_license`, `maximum_verdict`, `failure_scope`, and `unlocks`.
A prerequisite success activates the next unsatisfied obligation; a route
outcome changes only its licensed propositions.

Each completed route earns exactly one verdict: **established as stated**,
**refuted with a named mechanism**, or **blocked with the missing construction**.
`qualified` is an intermediate route status, not a terminal substitute.
Preserve `evidence_scope`; numerical uncertainty is not a physical refutation.
After failure, execute method repair, representation/reformulation, and
materially different candidate generation, or explain a step's inapplicability.
These are a minimum continuation ladder, not an exhaustion certificate.
The reward is useful information and a better next attempt, not route count.

The user owns the objective. Expand candidates append-only from historical,
external, or failure-generated ideas within its invariants and permitted imports.
Keep its positive intent whole. Scope repair earns credit only when it changes
what a downstream consumer can conclude; record the evidence that restores the
stronger statement. After two independent evidence passes, additional narrowing
requires new contrary evidence. Escalate repeated unsupported narrowing to the
user instead of compounding it.

## The ten completion achievements

Scientific success and headline promotion earn all applicable achievements:

1. **Object:** every conjunct of the requested positive object exists in its intended scope.
2. **Closure:** dependencies are accepted claims or approved imports, with inputs and parameters explicit.
3. **Natural fit:** accepted invariants survive, or a separate foundational revision earns their change.
4. **Exposing oracle:** the strongest practical check validates the actual claim with appropriate sensitivity evidence.
5. **Fair competition:** open mechanisms compete under preregistered structural criteria; a fixed theorem may use one complete proof route.
6. **Individual review:** each proposed/changed claim is reviewed; unchanged accepted dependencies retain authority.
7. **Consumers:** the impact-bounded downstream replay passes.
8. **Reusable code:** definitions/derivations are importable and tested; campaign scripts reuse them.
9. **Agreement:** registry, pinned release, generated documentation, and durable memory agree.
10. **Resolved in-scope debt:** hidden assumptions, unsupported promises, and broken consumers are discharged.

Explicit hypotheses, honest exclusions, and unfinished parent work are frontier,
not hidden debt. A conditional theorem, tangent, stationary saddle, simulation,
or linear mode meets the parent objective only when that is the object requested.

## Authority and the elite opening

Authority: **pinned release → accepted claims → supporting adjudicated campaigns
→ active proposals → append-only attempts/exploratory memory**. Commits establish
provenance; chronology, confidence, tally size, and empirical agreement do not
establish truth. Accepted canon governs releases while remaining challengeable.

At the start of durable work:

1. Read this contract, current release, relevant claim entries and source modules.
   For migration, locate the pinned source unit, disposition, and scope policy.
2. Search repository memory, verify facts at source, inspect git history/status,
   and preserve unrelated user changes. Reserve IDs by searching claims,
   campaigns, proposals, and memory, including rejected/provisional IDs.
3. Load [.agents/skills/physics-erdos-loop/SKILL.md](.agents/skills/physics-erdos-loop/SKILL.md)
   for physics/claim work; add [.agents/skills/theorem-synthesis/SKILL.md](.agents/skills/theorem-synthesis/SKILL.md)
   for composing accepted claims. Use `small-ratio-numerics` before designing or
   auditing near-floor force, splitting, soft-spectrum, or stability evidence,
   including reused machinery.
4. Instantiate the appropriate `memory-templates/` contract: base, objective,
   four levels, invariants, imports, target kind, candidate criteria, claim delta,
   consumers, and comparator exposure. A validated proposal schema earns source
   body/comparator access at the frozen boundary; disclose earlier exposure.
   Establish primary-source availability first. If an indispensable source for
   the requested objective is inaccessible, seek that source or a user-approved
   substitution while progressing independent authorized work.

Open mechanisms register at least two plausible concepts unless uniqueness is
proved. Fixed theorems register one complete route. Structural fit, assumptions,
parameter economy, symmetry, dimensions, limits, composition, and predictive
reach select concepts before empirical comparison. Comparators test a frozen
prediction; they are not disguised derivation inputs or post-hoc tolerances.
A new candidate is welcome; silently changing the objective is not.

## Earn the analytic construction before its numerical remainder

Use the typed chain in
[problem-deconstruction.md](.agents/skills/physics-erdos-loop/references/problem-deconstruction.md):
object → symmetry/conservation → ensemble/full functional → admissible space
and representation → analytic structure → observable → numerical remainder
→ approximation → verdict. Earn exact equations, complete variations, scaling,
conservation, bounds, limits, asymptotics and applicable theorems first.
Then name the irreducible proposition and freeze numerical design freedoms.
Exploratory samples retain that role; production evidence needs its own frozen
design and execution. “No closed form” alone does not exhaust analysis.

[oracles.md](.agents/skills/physics-erdos-loop/references/oracles.md) owns detailed
symbolic, formal, PDE, FFT, sensitivity, compatibility, and reproduction rules.
The small-ratio skill owns error budgets, licensed zero modes, residuals,
`lambda_min/lambda_2`, observed-order extrapolation and jitter tests; record
how applicable prescriptions were measured, bounded, or scoped below the floor.
Use rigorous enclosure for a computer-assisted proof; ordinary high precision
remains numerical evidence. Proof, applicability, and empirical adequacy are
separate achievements.

Capture exact source, command, environment, stdout/stderr, exit and elapsed
time on first execution. Keep failures append-only. Reuse the passing receipt
while code, inputs, and proposition are unchanged. Separate lexical check sites,
runtime executions, and assertion nodes; a tally is not a mathematical oracle.
Canonical APIs own equations, constants and conversions; thin campaign scripts
call them. Content/AST-anchored edits and small per-claim modules make errors
local and recoverable.

## Constructive review and natural fit

Use one substantive review and one correction check for a frozen claim
transaction. Review the strongest practical evidence and its logical bridge.
A direct falsifier, absent/circular load-bearing step, unsupported declared
dependency, or broken affected consumer earns a current correction. Adjacent
observations stay one-time follow-ups; new caution alone cannot promote them
into retrospective requirements. Group coherent evidence attachments by role
rather than reviewing every entrypoint as a claim.

Lead with the strongest supported statement, exact unsupported extension,
minimum repair, and its upgrade path. Preserve useful conditional/core/
interpretive/empirical layers. Review findings are rebuttable through evidence.
Correct only changed statements and affected edges in the correction pass;
metadata and prose changes do not commission another scientific review.

A candidate conflict earns diagnosis: repair or replace the candidate. A conflict
that survives independently earns a separate `challenges`/foundational proposal:
at least two repairs, minimum coherent change, migration map, independent review,
and full affected closure replay. Only accepted replacements use `supersedes`.
See [governance.md](.agents/skills/physics-erdos-loop/references/governance.md).
Earlier adjudicated campaigns remain immutable. Generate `docs/generated/`
with `scripts/render_docs.py`; edit migration dispositions and regenerate the
source-claims queue. Release membership follows acceptance, not whether an
epistemic status happens to be `active`.
Keep personal/historical memory outside the repository and the bundled memory
CLI as code only; repository memory records sourced framework work.

## Campaign continuity, pause, and scientific exhaustion

Bank intermediate utilities, subclaims, failed routes and receipts in campaign
commits. Their next parent obligation is the next achievement. A terminal
campaign PR records either complete positive success or certified exhaustion;
a milestone, utility or renamed “non-campaign” support change does not create
an early campaign PR. PR/merge activity is delivery scaffolding, not a scientific
reward or a reason to finish early. Independently requested process/software
work follows its own bounded objective.

Exhaustion requires the original, append-only-expanded candidate universe;
historical/external/failure-generated inventory; route verdicts; repair and
representation records; equivalence partitions; remaining-route inventory;
and coverage/no-go arguments for infinite classes. A distinct non-author/
non-implementer independently generates alternatives from the frozen objective
and sources before seeing the favored exhaustion conclusion; reconcile its
signed record and review the certificate. Reducing the universe requires user
approval. Effort, diminishing returns, absent ideas, or any fixed failure count
cannot replace coverage. Plausible remaining routes keep the campaign active.

Honor an explicit user stop or narrower task immediately. Save drafts, genuine
open questions, receipts, branch/session locations and next executable work;
perform only the requested preservation/validation. A pause is not scientific
completion. Runtime or external-authority interruptions receive the same honest
resume record. Resume scientific work on the user's authority, not template
pressure to keep working.

## PR lifecycle and proportional validation

Every PR names exactly one canonical issue that predates it, with objective,
scope, success, dependencies and coordination. Use `Advances #N` for an open
goal (including exhaustion), `Fixes #N` for complete positive success.
External PR harvest and terminal campaign review use
[research-pr-harvest](.agents/skills/research-pr-harvest/SKILL.md);
artifact merge, claim promotion and goal completion are independent decisions.
A user-supplied external PR authorizes its normal review/repair/merge lifecycle,
within scope; it does not authorize force pushes or unrelated deletion.

Preserve valuable units in `request changes`, `active refactor`, or
`active harvest` while a finite repair can land. The **terminal-close** test for
an unmerged PR is: every reusable unit landed elsewhere; every remaining unit
is evidenced incorrect/non-novel/unmaintainable; explicit owner/author withdrawal;
or a landed superseding implementation. Record rationale/replacement links.
If terminal-campaign review finds a real remaining scientific route, return to
campaign execution and recertify its terminal state before the campaign PR.

Use a distinct merger by default. The user/owner may explicitly authorize
author self-merge of a named PR or bounded change; record that override and
existing validation. It supplies no independent scientific review. Confirm
automatic deletion of the exact merged same-repository head; delete only that
verified head if necessary. Preserve main, protected, open and closed-unmerged
branches; retirement of an unmerged head needs explicit owner direction.

Use `scripts/validate_changed.py` for one impact-selected receipt:
`scripts/validate.sh --fixed-only`, `--pytest-scope <selectors>`, or `--full`.
An additive public export or leaf synthesis stays scoped with bounded known
consumers and unchanged existing contracts. Shared numerics/verification,
changed claims or governance semantics, dependencies, foundations, cross-sector
conventions, or uncertain impact earn full replay. Process prose/templates earn
syntax/frontmatter, affected process tests and whitespace checks; they do not
trigger scientific replay. Reuse receipts through review/merge; rerun only
invalidated checks. Run validation and commit separately so failure stays visible.
Periodic integrated-main full checks are separate from each PR.

After merge, update the issue with landed units, exact evidence, authority/goal
state and the next decisive action; synchronize memory. Promote scientific
claims only with individual review, registry, pinned release, generated records
and resolved closure. Apply only the scaffolding that advances this result.
