## A. Actual new-GPAW Extension chain

### Construction and persistence

- `G/dft.py:63-83`: `ExtensionInput.from_input()` accepts non-dictionary objects unchanged. Dictionary dispatch only recognizes the listed built-ins; a custom named dictionary is not automatically registered.
- `G/new/builder.py:184-185`: each parameter object is built with `ext.build(builder)`.
- `G/extensions/__init__.py:8-68`: runtime hooks include `update_potential(vt_sR, density)`, `update_non_local_hamiltonian(D_sii, setup, atom_index, dH_sii)`, `force_contribution(nt_r, vHt_r)`, and `move_atoms(relpos_ac)`. `build()` can retain setups, cell, positions, communicators, and precomputed channel tensors. There is no automatic derivative of arbitrary custom one-centre coefficients.
- Use `GPAW(..., legacy_gpaw=False, extensions=[custom_input], spinpol=True, symmetry='off', ...)`, with the registered magnetic state and material settings. Do not use `external=`: `G/dft.py:1144-1152` routes non-null legacy external input to old GPAW.
- `todict()` is needed for parameter serialization (`G/dft.py:959-961`). New-GPW restart supports `object_hooks={'extensions': decoder}` before rebuilding parameters (`G/new/gpw.py:238-247`). Passing the input object during a fresh calculation is not, by itself, a complete recovery implementation. `calc.new()` serializes existing parameters (`G/new/ase_interface.py:371-377`); explicitly replace the extensions list with reconstructed input objects when cloning custom extensions.

### Potential, energy, and force placement

1. `G/new/pw/pot_calc.py:92-147` constructs ordinary XC/Hartree/local potential. `update1pw()` occurs before Poisson; simply imposing a scalar potential does not require changing that charge/Poisson hook.
2. `G/new/pot_calc.py:106-132` calls `ext.update_potential()` and adds its returned scalar to the external-energy accumulator. It then subtracts the smooth-potential expectation from the band-derived kinetic energy, with smooth-core bookkeeping.
3. `G/new/pot_calc.py:139-161,177-205,239-258` constructs PAW atomic Hamiltonians and invokes `update_non_local_hamiltonian()`. The returned energy from that hook is accumulated into the **XC-labelled** one-centre correction; the code then subtracts the complete `D*dH` expectation in the kinetic correction. The label is bookkeeping, not a physical declaration that an external term is XC.
4. `G/new/pwfd/wave_functions.py:368-392` computes projector-motion forces using the updated `dH`, and also the eigenvalue-times-overlap correction. Therefore PAW projector motion is already present when a custom scalar operator has been added correctly to `dH`.
5. `G/new/pw/pot_calc.py:166-206` differentiates smooth core against the total smooth potential, and calls the explicit extension-force hook. Compensation-charge and ordinary local-potential forces remain their existing contributions.
6. `G/new/calculation.py:347-391` assembles those forces, domain-reduces ordinary terms, adds the extension contribution **after** that reduction, then symmetrizes and broadcasts. The extension must deliver the complete explicit contribution in the convention expected on the final master; it must not assume GPAW will domain-sum it afterward. The existing D3 extension returns a full force array, already broadcast (`G/extensions/d3.py:24-58,95-123`).

Consequences:
- Supply force arrays shaped `(Natom, 3)` in atomic units, Hartree/Bohr. `G/new/calculation.py:63-66,321-344` converts to eV/Å at the external interface.
- Disable unlicensed symmetries: an arbitrary cos/sin source generally does not retain the unperturbed point group, and the final force symmetrization would otherwise alter the response.
- The explicit force hook has no density/PAW arguments beyond its two grid arguments. Cache the required current density-matrix and channel data during the potential update, or otherwise arrange complete current data in the built extension. Do not rely on every rank executing every atomic Hamiltonian hook: that loop is atom/k-band distributed.

### Complete source operator and term accounting

The following is a **proposed construction to be checked**, not an executed result. Use electron potential energy `vλ(r)=λ f(r)` in Hartree, with f a declared cosine or sine. Distinguish it from electrostatic voltage φ; for electrons v=−eφ.

For the frozen-core all-electron number-density source, account separately for:
1. smooth-grid contribution, using the sum of the two density components;
2. valence PAW augmentation `Σa,ij Dᵃij Δvᵃij`;
3. rigid frozen-core-minus-smooth-core contribution `Σa ∫(ncᵃ−nctᵃ) vλ`;
4. **only if the imposed source is an actual electrostatic source coupled to total charge**, the direct nuclear term `−Σa Za vλ(Ra)`.

The reconstruction establishing precisely these electronic terms is `G/densities.py:89-148`. `G/new/density.py:142-148,231-238` shows that the smooth density already includes the smooth core, split between spin components. It must not be added twice.

Two clean energy-hook conventions are possible; choose and preregister one:
- Return the entire external functional, including augmentation and direct/core terms, from `update_potential()`. Add the augmentation operator in `update_non_local_hamiltonian()` and return **zero** there.
- Or return only smooth plus rigid terms from the smooth hook, and return the augmentation energy from the nonlocal hook, respecting its atom/MPI reduction and its XC-labelled storage.

Do not combine these conventions. The first avoids having an external contribution stored under the XC label and permits all explicit-force data to be cached together.

For forces, separate:
- projector-motion terms: already handled by the existing updated-dH force path;
- smooth-core motion: already differentiated against the total smooth potential;
- **explicit motion of the augmentation coefficient Δvᵃ**, from its dependence on Ra;
- explicit frozen-core correction and, when declared, direct nuclear force.

The last two items belong in the extension force contribution. Adding only smooth v and PAW Δv to the Hamiltonian leaves these explicit derivatives unaccounted for. Conversely, adding projector-motion or the smooth-core term again would double count them.

If the retained electronic channel is **valence all-electron density**, not total electron density, replace the rigid core correction in the functional by the negative smooth-core contribution, so the already-present smooth core is removed. This also changes the explicit force needed to cancel its automatic smooth-core derivative. Alternatively calculate the full-source response and subtract the analytically identified rigid-core/direct-nuclear cross response. State which observable is being returned.

The direct term is not permission to put bare proton charges on phonon coordinates. It is the known coupling of the actual nuclei to an explicitly declared imposed electrostatic source. After projection onto retained modes, the electronic vertex must be separated from that direct term according to the chosen retained-density convention.

### What the zero-energy return means

`G/new/external_potential.py:43-59` adds a smooth constant-field potential and returns zero, with no scalar-field PAW/explicit-force override. It is not a suitable periodic Ni implementation, and no sawtooth is recommended.

A zero return is **not by itself** evidence either of correctness or of missing physical energy. BField, for example, uses a nonzero complete smooth-hook energy and a zero nonlocal-hook energy (`:72-111`). ### Restrictions that matter for Ni

1. **LCAO projection, not PW projection.** Displacements may use PW, but both supercell projection and final primitive electronic coefficients are LCAO. Basis convergence and consistency with the electronic bath remain obligations. Passing an arbitrary saved-PW ground state to `bloch_matrix()` does not provide the required LCAO coefficients.
2. **Matched grids:** the finite-difference coarse grid must match the LCAO projection grid. The official tutorial documents explicit PW `gpts`; the installed dictionary factory derives grid and spin from the displacement cache (`G/elph/supercell.py:55-96`). Use the same setups/XC and magnetic state, not only the same array dimensions.
3. **Projection MPI:** `G/elph/supercell.py:223-226` requires domain and band communicator sizes one. K-point parallelism is the supported distribution. The final Bloch stage is safest serial; new compatibility coefficient access itself asserts k-point and band communicator sizes one (`G/new/backwards_compatibility.py:191-202`).
4. **Full electronic BZ:** `G/elph/gmatrix.py:284-317` requires `nbzkpts == nibzkpts` and finds actual k+q partners. Use `symmetry='off'`, including time-reversal reduction off. The new builder separately applies the time-reversal setting (`G/new/builder.py:114-127`).
5. **Spin:** `displacements.py:37-40` explicitly processes the collinear channels separately and warns to use care; noncollinear calculations are unsupported. The dictionary projection factory accepts one or two spin channels. The `TightBinding.bloch_to_real_space()` time-reversal restoration has a one-spin assertion in its reduced-BZ Gamma branch (`G/lcao/tightbinding.py:107-131`). For magnetic work pass a full, explicitly configured LCAO calculator with symmetry off, rather than relying on the factory's point-group-only disabling.
6. **Raw modes:** `ElectronPhononMatrix` otherwise calls `phonon.read(symmetrize=10)` (`gmatrix.py:126-128`); ASE defaults include Frederiksen force adjustment and acoustic restoration (`ASE/phonons.py:382-475`). Preloading the raw `Phonons` object avoids this. `bloch_matrix()` otherwise zeros its first three Γ couplings (`gmatrix.py:323-324`). Do not enable either silent correction.
7. **Normalization:** `prefactor=False` removes the square-root frequency prefactor, but it does **not** remove contraction with ASE's mass-scaled phonon vectors. ASE uses eigenvectors multiplied by inverse square-root atomic masses (`ASE/phonons.py:755-763`). Keep raw Cartesian vertices and the precise mode map. Do not treat the returned mode matrix as a unit-displacement Cartesian derivative merely because the docstring labels eV/Å. `prefactor=True` also has an unresolved mass-convention comment in the installed source (`gmatrix.py:221-230`); avoid it until independently checked.
8. **Unstable modes:** ASE preserves negative eigenvalues as signed negative frequencies (`ASE/phonons.py:768-791`). Keep these and raw force constants. Do not apply a positive-frequency quantization prefactor to an instability.
9. **New versus legacy response bridge:** automatic LCAO-to-PW conversion in `ResponseGroundStateAdapter` is explicitly guarded by `calc.old` (`G/response/groundstate.py:59-65`). New-LCAO response is not transparently converted by that branch. Combining new-PW χ with an LCAO vertex requires a demonstrated common-state/operator map. An explicitly authorized old-LCAO representation is a separate approximation/engine choice, not a silent fallback.
10. **Indices:** pass a NumPy index array. In the installed `ElectronPhononMatrix.__init__`, assignment to `self.indices` is inside the NumPy-array branch (`gmatrix.py:75-80`); a caller-supplied plain list is not equivalently handled.

### Two important exactness prerequisites in the installed B path

**Reference-cell projector indexing — source-level concern, not an executed bug verdict.** ASE displaces `offset*Natom + a` when `center_refcell=True` (`ASE/phonons.py:85-94,190-216`). For an axis-two supercell that offset is nonzero. In contrast, the installed projector-derivative piece uses `dH_asp[a]`, `P[a]`, and `dPdR[a]`, and the caller passes primitive a without adding the offset (`G/elph/supercell.py:150-167,285-289`). I found no corresponding offset remapping in that call chain. Before trusting a 74-atom B vertex, explicitly compare centre-cell versus translated/corner-cell constructions, with the PAW projector term isolated. This may require an owned upstream/library repair; do not hide it by dropping the nonlocal term.

**Image truncation / R=0 extraction.** The installed code Fourier-transforms the supercell Bloch matrix and keeps only the supercell R=(0,0,0) block (`supercell.py:271-306`); at Gamma it warns that overlap with neighbouring cells cannot be removed (`:261-264`). A small displacement supercell can represent a periodic q channel without the public real-space interpolation being exact. Check image contributions and basis range, or retain the full Bloch matrix rather than silently treating the R=0 block as complete.

For Γ specifically, the internal `_calculate_supercell_entry()` returns the full per-k matrix before R=0 extraction. It offers an implementable fixed-equilibrium-LCAO projection route with explicit coefficient contraction; it is an internal API and still needs a force/energy derivative oracle. It is not an existing public PW vertex API.

Finally, the four potential/projector terms are not themselves a proof of a total-energy/eigenvalue derivative. The new force source explicitly contains the overlap correction, while this elph assembly contains no separate overlap-derivative term. For a claimed energy derivative, preregister a generalized-eigenproblem/PAW-overlap and moving-basis comparison. Do not assume either that the documented potential vertex is missing that term in its own convention, or that it is automatically identical to the force-consistent derivative required by P254.

## Cell/q support and actual calculation counts

Let the loaded 37-atom structure be the declared reference cell. These are representational statements with prospective translation/Fourier oracles, not convergence claims.

- **37 atoms, Γ with G≠0:** periodic scalar density patterns inside that cell. They are microscopic channels, not a uniform optical electric field.
- **74 atoms, S=(2,1,1)** or an axis permutation: supports the corresponding half-reciprocal-vector q of the 37-atom lattice, as a periodic pattern in the doubled cell. Include the registered reciprocal G offsets and real quadratures.
- **S=(1,1,1) displacement construction:** source API permits it. It can supply a declared Γ periodic-displacement derivative. Arbitrary q returned by subsequent interpolation does not make missing intercell information exact.
- **Axis-two displacement construction:** source API permits it and can target the associated limited commensurate q channels. The B interpolation and reference-cell caveats above still apply.
- **S=(2,2,2):** represents the eight binary half-grid q points of that reference lattice; it is not required merely to obtain Γ plus one axis-half-q slice, and is not automatically supercell-converged for full three-dimensional electron–phonon coupling.

A 74-atom cell obtained by relaxing away its 37-atom translation symmetry cannot be relabelled as a clean q sector of the original 37-atom structure. Require geometry and magnetic translation oracles before folding/unfolding. Likewise, an arbitrary finite q is only accessible when the electronic k mesh contains the needed k+q states.

**Source-fact counts, no timings:**
- A: with M independent real retained scalar channels and A amplitude magnitudes, central force response costs `1 + 2*A*M` fixed-geometry SCFs per cell/settings set if all fresh, counting one zero-source baseline. Each perturbed SCF supplies all atomic force components. HF/mixed-displacement validation adds its own stated displaced geometries; it is not included for free.
- B: ASE performs one equilibrium SCF plus six displaced SCFs per selected reference atom: `1 + 6*Nselected` per displacement amplitude/settings set (`ASE/phonons.py:163-216`; official tutorial explicitly says `2*3*N` displacements). Supercell repetition changes the atoms per SCF, not this reference-atom count. Full 37-atom reference displacements run at 37, 74, or 296 atoms for S products 1, 2, or 8 respectively. Choosing 74 atoms as a new base cell instead changes Nselected accordingly.
- B also needs LCAO projection initialization/linear algebra and a separate converged primitive full-BZ LCAO electronic state. Projection initialization is not a further required self-consistent SCF in the installed dictionary path. Frequencies/q lists do not rerun the displacement SCFs, but do add projection work/storage.
- Symmetry reduction is not automatically provided by this displacement loop. Any reduction must carry independently checked atom/vector/channel maps.

For actual finite q, the matrix-returning finite-q API above is the less ambiguous initial source check. An exactly repeated doubled cell supplies a useful independent fold/unfold comparison after normalization and sampling are matched.

### Metallic static and spin consistency are real outstanding constraints

- `G/response/chi0_base.py:140-142` weights transitions by occupation differences. Equal-band diagonal occupation derivatives are not generated by multiplying this difference.
- The separate optical intraband correction is added to the **head**, not the complete microscopic body (`G/response/chi0.py:338-344,360-409`).
- Therefore a thermodynamic static finite-smearing Γ SCF response is not automatically the ω→0 value of this collisionless microscopic matrix. Fixed N versus fixed chemical potential and the order of limits must be stated and checked.
- A spin-PBE SCF force response also includes the PBE induced-XC response, whereas χRPA does not. Installed `DensityXCKernel.__post_init__` asserts `nspins == 1` (`G/response/density_kernels.py:13-35`). It does not provide the matching collinear spin-PBE microscopic kernel.

Thus an exact same-approximation spin-PBE-SCF ↔ dynamic-χ static-consistency oracle is **not supplied by this installed density-kernel API**. This is a specific missing construction, not a reason to make Ni nonmagnetic. Either construct a demonstrably matching response calculation, or explicitly retain the difference as a modelling approximation and prove the later static matching for the actual supplied operators.

## Saved-band streaming and memory

The existing memory-model receipt accurately describes the traced path, with these boundaries:

The new compatibility property evaluates `data[:] * scale` when scaling is required (`G/new/backwards_compatibility.py:320-332`); the ASE interface builds that compatibility object with PW scaling enabled (`G/new/ase_interface.py:528-540`). It therefore reads and scales the **entire saved band block at one spin/k point**, then FFTs selected bands. It is not true saved-band streaming.
- `ASE/io/ulm.py:642-668` does support individual/sliced-band reads. The native new accessor `calc.wfs.get_wave_function_array(n,k,s,...)` takes an individual native band (`G/new/backwards_compatibility.py:191-213`), and the native collection path accepts band ranges. Those capabilities do not mean the current dielectric pair path uses them.
- `make_sure_wfs_are_read_from_gpw_file()` explicitly materializes all lazy arrays when invoked (`G/new/ibzwfs.py:538-545`). Force/SCF operations invoke it; opening a response adapter alone is not the same operation.
- `nblocks=1` remains the configured no-BLACS choice. Its χ0 body stores all frequencies and all G×G entries on each matrix block communicator of size one; the Hilbert path can allocate a second spectral array (`G/response/chi0.py:239-268`). - B's `load_sc_as_needed=True` only limits loading of the supercell cache. Public `bloch_matrix()` still collects all primitive LCAO coefficients for a spin, precomputes all selected-displacement ket contractions, and allocates the full output (`G/elph/gmatrix.py:142-150,237-252,295-307`). It is not a fully streamed final vertex API.

No 37-/74-atom memory feasibility result follows from the native Ni1 pilot or from dividing a GPW file size by MPI ranks. Budget the actual active coefficient blocks, real-space pair buffers, PAW tensors, χ0/Dyson copies, and output tensor. Process one q/frequency batch at a time only where the actual solver/distribution permits it; do not claim a nonexistent streaming option.

import numpy as np
import gpaw
from gpaw.setup import create_setup
from gpaw.response.groundstate import ResponsePAWDataset
from gpaw.response.paw import calculate_pair_density_correction

gpaw.setup_paths.insert(0,
    '/home/administrator/projects/catalyst-dft/.venv/lib/python3.12/site-packages/gpaw_data/setups')
K = np.array([0.17, 0.29, -0.13])

for symbol, kind in [('Ni', '10'), ('H', 'paw')]:
    setup = create_setup(symbol, xc='PBE', type=kind, lmax=2)
    paw = ResponsePAWDataset(setup, radial_points=2**10)
    Q0, Qp, Qm = calculate_pair_density_correction(
        np.array([np.zeros(3), K, -K]), pawdata=paw)

    np.testing.assert_allclose(Qm, Qp.conj(), rtol=1e-12, atol=1e-12)
    def quadratures(r):

        return np.array([z.real, -z.imag])

        fd = (quadratures(R + dr) - quadratures(R - dr)) / (2*h)

        exact = np.array([dz.real, -dz.imag])

        if v == 0:
            assert not np.allclose(fd, -exact, rtol=1e-6, atol=1e-9), \
